# Health, market eligibility and Polygon observation contract

SYSTEM_READY requires all existing non-book checks plus an identified, connected, synchronized, fresh technical book stream. This remains a conservative readiness subset: funding, allowance, risk and reconciliation checks are retained, not silently relaxed. MARKET_ELIGIBLE_NOW requires the actual fresh two-sided valid book. Decision signals/risk gates remain separate; neither output submits or arms. ready_for_arm retains the old conjunction, submit_allowed is always false.

Two full snapshots with valid identity/schema but an empty side are synchronized observations of a non-tradeable market. Keep the exact empty sides and apply subsequent valid deltas; do not synthesize liquidity. available and book_synced retain their strict trade-gate meaning (false when empty); synchronized describes stream initialization. Technical RESYNC_COMPLETE does not imply eligibility. CROSSED_BOOK, ambiguous source time, regression, incomplete resync and stale observations stay fail-closed. The -16 ms pre-snapshot case is unchanged and remains supersession-unproven.

Polygon timestamps are consensus metadata, not client receipt times. Official Bor source https://raw.githubusercontent.com/0xPolygon/bor/develop/consensus/bor/bor.go (verifyHeader and EarliestAnnounceTime, inspected 2026-09-25) explicitly implements early announcements in fork-dependent branches. We do not claim that this development version is the deployed target or infer its numeric limits. Therefore the client does not invent a future-time allowance or implement consensus validity by comparing to Windows time. Provider trust and finalized hash/height checks remain explicit. Timestamp skew is reported, never used to refresh inventory. https://docs.polygon.technology/pos/concepts/finality/finality documents the finalized tag.

Reports retain block timestamp, request start, receipt, both deltas, local UTC time.time_ns source, CLOB /time sample and its integer-second offset interval. CLOB seconds cannot certify 500 ms clock accuracy; accuracy_500ms_proven=false is explicit. No clock is adjusted. The 500 ms gates still measure original observation ages on the local process clock; they are not a claim of subsecond absolute UTC calibration.

New manual mode --target-machine --health-contract: qualify finalized, verify Genesis/cursor hashes, scan only cursor+1..B, then fixed B+1..H. Concurrently acquire four account GETs and a new canonical H witness plus numeric B hash recheck. No tail gap and no endless retries; advanced H, reorg, incomplete/old generation => blocked. Preserve scan_observed_ms; observed_ms is the NEW remote witness request start, not a retimed scan. Reconcile actual account/indexer/known asset data against unchanged Genesis. Scoped provider/indexer/credential limitations persist.

The new mode does not append a recovery event to the existing ledger: it reports recovery required and remains blocked. Cursor checkpoints are separate additive artifacts. No BTC V1 change, no order transport attachment, no flags enabled.

Existing tests expecting EMPTY_BOOK to raise were explicitly updated to assert synchronized but unavailable, no liquidity construction, and NO_TRADE. Previous future-header test now asserts skew diagnostics instead of a cross-clock consensus decision. Crossed/regression, freshness and monetary lock tests remain.
