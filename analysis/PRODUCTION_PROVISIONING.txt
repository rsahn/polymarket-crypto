A. PRODUCTION_EVIDENCE_SOURCE

Interface : production_evidence_source.ProductionEvidenceSource(provider,
authority=ProductionAuthority(...), account, collateral, session, baseline, clock).
provider.snapshot() et provider.execution(order_id) sont async. La source impose
un timeout de 5 secondes, sérialise les lectures et valide chaque observation.
Le provider concret livré est production_provider.EvidenceInbox(directory).
Il lit des fichiers ; il ne contacte aucun endpoint et ne produit aucune preuve.
AccountAdapter réalise ensuite normalisation, identité, lineage et réconciliation.

Fichiers dans un répertoire réel hors Git, documents <= 8 MiB, publiés par rename
atomique, sans doublons JSON, NaN/Infinity ni liens de fichier :
  baseline.json : baseline signé, figé pour la session ;
  snapshot.json : inventaire complet actualisé signé ;
  qualification.json : observed_ms global + 14 enveloppes signées ci-dessous ;
  market.json : slug, condition_id, outcome_tokens {UP,DOWN}, expiry_ms ;
  next_market.json : même forme pour les rotations ;
  execution-<SHA256 UTF-8 order_id>.json : exécution signée quand nécessaire.
Les métadonnées market sont liées aux preuves signées par validate_assembly.
Pas de demande d'exécution artificielle ni de trade pour créer un fichier.

Enveloppe baseline/snapshot : kind, key_id, provider, account, signer, collateral,
session, trust_policy_digest, observed_ms, valid_until_ms, provenance_signature,
scope='wallet', atomic_frontier={sequence,digest}, inventory, coverage, cash,
positions, trade_ids, open_orders, terminal_order_ids, inventory_proven=true,
cash_proven=true, orders_complete=true, trades_complete=true,
positions_complete=true. Snapshot : baseline_digest, ancestor_frontiers,
experiment_trade_ids, foreign_order_ids également nécessaires à l'adapter.
Montants : décimaux non négatifs et finis, unités explicites/normalisées.
Voir adapters.py pour les champs d'observation et clocks supplémentaires.

Définition exacte de complétude acceptée par le consumer :
  inventory possède cash, positions, orders, trades, fees ;
  coverage possède exactement ces 5 clés ; pour chacune :
    scope='wallet', filters={}, frontier identique à atomic_frontier,
    complete=true, next_cursor=null, origin='wallet_creation',
    count=len(inventory[composant]), digest=core.digest(inventory[composant]).

  quand le frontier avance. Ce frontier applicatif n'est PAS en soi un bloc

  trades : leurs id, dans l'ordre, égalent trade_ids.
  orders : terminal est un vrai bool ; false -> open_orders, true -> terminal_order_ids.

  experiment_trade_ids ; foreign_order_ids vide. Activité étrangère bloquante.
  Baseline observé <=5 s au chargement initial, validité <=259200000 ms.
  Snapshot observé <=5 s et validité <=5000 ms. Jamais restamper un vieux relevé.

Rôles à assigner explicitement : provider pour inventaire/exécution et preuves
1,2,5 ; marché/risque pour 3,6 ; qualification technique pour 4,8,9,10,11,12,13 ;
custody pour 7 ; réviseur indépendant pour 14. Cette répartition est une
proposition de provisioning, pas une policy préapprouvée. La receipt authority
de custody est un autre objet, pas automatiquement une key de cette policy.

Signature : EIP-191 secp256k1. Retirer seulement provenance_signature de
l'enveloppe ; sérialiser via core.encoded (JSON trié, compact, ensure_ascii par
défaut, NaN interdit ; Decimal en chaîne), puis signer encode_defunct(text=

Le verifier récupère l'adresse, compare key_id/address/kinds/provider/context
et trust_policy_digest. kind, s'il accompagne check, doit lui être égal.
policy digest = core.digest(policy), SHA256 du JSON canonique UTF-8, PAS le hash
des octets indentés du fichier. Le digest APPROUVÉ doit arriver par un canal
indépendant ; son calcul local ne constitue aucune approbation.

provider, account, signer, collateral, session, market=condition_id,
