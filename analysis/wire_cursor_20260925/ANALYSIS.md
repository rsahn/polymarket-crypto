# D6 wire and inventory cursor investigation

Reference report: D6_POST_GENESIS_READINESS_20260925_141502_295752.json. Raw initial WS frames were not retained there. Its last attempted token depths were 99/0 and 0/99; they cannot retrospectively establish the exact first message payload. No live feed was queried during this change.

Official API wire documentation: https://docs.polymarket.com/market-data/realtime-data (API Market Stream, Order Book and Price Change). One book message uses event_type=book, market, asset_id, timestamp, bids[], asks[]. Price changes are per asset_id with BUY/SELL. The implementation directly reads those side names, matches asset_id against discovered UP/DOWN IDs and applies BUY to bids / SELL to asks. Arrays of messages are iterated as independent per-token books, not split into bid/ask snapshots. Pre-snapshot deltas are ignored, never applied to fabricate initialization. No demonstrated wire parser defect justifies changing this mapping.

Installed polymarket-client 0.11.0 parse_market_event accepts a synthetic book with one bid and an empty asks list (EVIDENCE.json). Thus an empty side is representable in the SDK/protocol; it is not proof of a parser inversion. D6 still requires both nonempty sides and rejects it as EMPTY_BOOK. No reconstruction from the other token, complementary prices, REST or last trades is introduced.

Instrumentation now retains the first full-book summary per token/generation BEFORE liquidity/freshness validation. Identity is a token index and SHA256 of the public asset ID, plus exact identity-match boolean; no full token/account identifier or raw payload. Fields: message kind, side counts, best bid/ask, source timestamp, generation. First summaries survive later invalidation. Transition entries carry the exact reason. States: CONNECTED, INITIAL_SNAPSHOT_PENDING, SYNCHRONIZED, STALE, INVALID_BOOK, DISCONNECTED. Existing availability/freshness/500 ms constraints are unchanged.

Inventory bug: each new process used incremental_inventory(genesis), replaying already scanned post-genesis blocks. The runner now requires a cursor and never falls back to that initial scan. A separate immutable atomic checkpoint (runtime/d6_inventory_cursors) records complete scoped scan evidence and a checksum bound to the genesis snapshot hash; it never edits Genesis. Each catch-up selects the head once, verifies the previous cursor hash, then scans cursor+1 through the selected head. Account reads start after successful catch-up, alongside the existing fresh remote latest-head witness. Every failed generation attempt retains its reason and scanned watermark. No timestamp is refreshed by loading or saving a cursor.

Bootstrap limitation: old redacted local reports may seed a cursor only when they reference this exact unchanged Genesis, are marked MANUAL_TARGET and explicitly report zero events/zero checked assets. Nonempty redacted evidence cannot reconstruct balances. Remote cursor hash and genesis anchor must still be checked before use. Existing local artifacts are trusted as local evidence, not as signed remote attestations. Missing, corrupt or conflicting evidence blocks; no historical fallback. Future complete checkpoints avoid this legacy-report bootstrap. Latest successful scan is checkpointed even when final readiness fails.

Tests RED then GREEN, plus full offline harness (512 passed and 8 subtests). Scope remains D6_POST_GENESIS_READINESS. No qualification rerun, no credential/private-key load, no monetary SDK invocation, no Genesis/BTC V1/risk/flag change. Network readiness is not newly asserted. Actual first full-books still require a later manual target observation; no identical run was launched here.
